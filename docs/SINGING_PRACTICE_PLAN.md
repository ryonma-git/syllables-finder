## 1. 今回の決定

「読む／歌う」は維持し、「歌う」の中に次の独立した操作を置く。

| 操作 | 選択肢・初期値 | 意味 |
|---|---|---|
| 表示 | 詳細 / 一覧（初期） | 詳細は約2小節を大きく、一覧は複数小節を段組で見渡す |
| 音高表示 | ピアノロール（初期） / 楽譜 | どちらも同じ音符・歌詞・再生位置を投影。C4等の音名を残す |
| 再生範囲 | 曲を通して（初期） / 選択範囲を1回 / 選択範囲をループ | 表示中の2小節だけに再生を限定しない |
| 表示補助 | 読みON、IPA OFF、再生位置に追従ON | 「読む」は従来どおりIPAと読みを表示 |

一覧は歌唱練習の入口。標準幅では4小節/段、狭い幅・文字拡大時は2小節/段。
1段も収まらない場合は横スクロールし、文字を極端に縮めない。詳細は2小節単位の前後ボタン。
一覧の小節を選び「詳細で見る」で対応する2小節へ移る。一覧へ戻っても選択と位置を保つ。
読む画面のPhrase一覧は歌詞のナビゲーションとして維持する。
一覧では現在の大きなPhrase見出しを曲名・小節範囲の小さな見出しにし、歌詞は各段に置く。
詳細には、その2小節に重なる歌詞・訳を表示する。Phraseを2小節に再分割して保存しない。

```text
読む / 歌う          詳細 / 一覧          ピアノロール / 楽譜
                    読み ✓  IPA □        再生位置に追従 ✓
一覧:  [小節1][小節2][小節3][小節4]   ← 原文・読み・音符を同じ拍位置に
       [小節5][小節6][小節7][小節8]
       [小節9][小節10][小節11][小節12]
詳細:  前へ  [小節1             ][小節2             ]  次へ
再生 / 一時停止 / 停止   曲を通して ▼   選択: 1–2小節   テンポ
```

## 2. 小節・歌詞の投影

- `Beat`（四分音符単位の有理数）が時間の正本。`Measure.range`を小節境界に使い、`number`は表示文字列として扱う。配列順/番号の大小から時間を推定しない。
- 各段で同じpixelsPerQuarterを使う。`x = 段の音楽領域左端 + (beat - 段開始beat) × scale`。4/4の同じ長さの小節は同じ幅、弱起・不完全小節は実際の長さに比例する。段末の不足小節を引き伸ばさない。
- 拍子分母の1拍は`4 / denominator`四分音符。小節番号と小節内拍を表示する。6/8は8分音符6拍、テンポ表示には四分音符基準と分かるラベルを付ける。
- 保存済み小節があれば優先。隙間は「小節未設定」の時間区間として保持。重複する小節は小節投影エラーを示して拍時間軸へ退避し、開く/編集/保存まで拒否しない。
- 小節情報が全くない場合だけ、拍子マップから表示用小節を派生する。途中の拍子変更で区切り、最後の端数も保持。「推定小節」と表示し、文書へ自動書込みしない。時間範囲のない歌詞は読む画面で扱う。
- 詳細の窓は先頭から2小節ずつ（最後は1小節も可）。一覧はこの小節列を段に詰める。Phrase境界や改行で時間を詰めない。大曲は段単位のLazy表示、現在の128拍制限を表示窓に置き換える。
- イベント・Alignmentは表示窓と交差するものを取得し、描画だけ窓端でclipする。小節をまたぐ音は同じevent IDの断片。データを分割せず、発音も繰り返さない。
- 音節ごとの対応区間を表示する。離れた対応区間の間を一続きの発音と偽らず、メリスマの継続線等で区別する。休符・無音も本来の幅を残す。
- 長い語は折返し/複数行と詳細表示で読む。語の文字数で小節幅を変えない。将来の単語幅モードは別の座標投影にし、onset/duration/Alignmentを変更しない。今回は無効な切替ボタンを置かない。

## 3. 選択・再生・追従の契約

状態を `editingSelection`、`practiceRange`、`viewport`、`transport` に分ける。
文書へ保存しないsession stateとし、初期practiceRangeは最初の2小節。

| 操作 | 結果 |
|---|---|
| 歌詞/Phrase/音符をクリック | 編集対象と表示位置だけ変更。音を止めず、再生位置も変えない |
| 小節クリック、Shift+小節クリック | 最初/最後の小節を選びpracticeRange候補を表示。範囲再生中の変更は下記の明示適用で行う |
| 「表示中の2小節を練習」「このフレーズを練習」 | 前者は詳細窓、後者はPhrase範囲を包含する小節範囲をpracticeRangeに設定。再生モードは自動変更しない |
| 「選択範囲を1回/ループ」へ変更、または範囲再生中に「範囲を適用」 | 再生中なら一時停止し新しい範囲先頭へ。再開は再生ボタン。停止中も範囲先頭へ |
| 小節目盛りの明示的なシーク操作 | 音とplayheadを同じ位置へ。再生中はそこから継続、停止中は位置だけ変更。範囲外は範囲内へclamp |
| 一時停止 / 再開 | 同じ位置から継続。範囲末尾なら次回の再生は範囲先頭から |
| 停止 | 音を止め、現在の再生範囲先頭へ戻す。曲通しなら曲頭 |
| 表示/音高表示/読む・歌うの切替 | 再生と選択範囲を維持。読む画面でも再生中はtransportを操作できる |
| 手でスクロール、前後の表示窓へ移動 | 追従をOFFにする。音は継続。「再生位置に追従」で現在位置へ戻れる |
| 再生が次の2小節へ進む | 追従ONなら詳細窓を切替。一覧では演奏中の段を可視範囲へ。音声の再開始をしない |
| テンポ変更 | ドラッグ終了時に一時停止位置から新テンポで準備・再開。短い準備時間は可。文書のテンポは変更しない |
| 言語情報/Alignmentのみの編集 | 再生を継続して表示を更新 |
| 音符・テンポ・小節等の音楽編集/そのUndo | 再生を一時停止して計画を破棄。位置を新範囲内に補正し、再生ボタンで再開 |
| 文書の置換/ウィンドウを閉じる/音声デバイス構成変更 | 再生と準備をcancel。古い完了通知で再生を再開しない |

practiceRangeの編集中候補と適用済み範囲を分け、表示だけ変えた時にloop範囲が動かないようにする。
曲通しの範囲は0から小節/イベント/有効なPhrase時間範囲の最終端まで。先頭・途中・末尾の休みを保持する。
全曲の`music.events`を一度だけ時刻順に扱う。各Phraseの音符リストを連結しない（共有IDの二重発音を防ぐ）。
音符のない曲では再生を無効にして理由を表示。範囲に音符がなくても曲に音があれば無音区間として時間は進む。
曲末尾では停止して末尾を表示。ループだけ範囲先頭へ戻る。楽譜の反復記号による展開は今回扱わない。

## 4. 音声実装の決定

現行`GuideTonePlayer`はPhrase限定・一定BPM・main actorで全PCM生成・UIの33ms監視で再スタートする。
ページ送りやループのたびにこの処理を呼ぶ方法は廃止する。

### 計画と時間変換

- SongCoreに純粋な`TempoMap`（beat↔seconds）、`PlaybackPlan`（範囲/発音列/終了時刻）を追加。型名は目安。音声SDKを入れない。
- テンポマップを区間積分する。練習テンポは曲頭BPMに対する倍率として全テンポに適用し、途中のテンポ変化を保つ。96→48なら全区間2倍の秒数。UIは曲頭基準の四分音符BPMと倍率を表示する。
- イベント境界は絶対時刻から一貫した丸めでsample indexに変換する。小節ごとの丸めを足し合わせない。総frame数は終了時刻を切上げる。
- 小節跨ぎは音を切らない。別イベントは同音でも再発音。明示された同一tieGroupIDで同pitch/channel/track、時間的に連続する場合だけガイド音を結合する。矛盾するtieは通常音として鳴らし診断を返す。
- 重なるnoteはmixし、velocityを反映してclipを防ぐ。現在の「先頭の1音だけ採用」は引き継がない。休符は無音。シーク/範囲端は音をclipして数msのfadeでクリック音を抑える。

### 初期の音声バッファ方式

短い教材の安定した連続再生を先に完成させる。今回は44.1kHz/mono/Floatの範囲全体PCMをバックグラウンドで生成する。
再生範囲は練習速度で**最大5分**、1本約53MB。予約するPCMはループ再開用の残部を含め最大2本とし、曲ごとの無制限キャッシュを作らない。
workerの一時配列と再schedule時の旧bufferも寿命を限定し、cancelした生成結果を保持しない。上記53MBをアプリ全体の最大メモリとは扱わない。
上限超過は生成前に検出し、短い小節範囲を選ぶ案内を出す。5分超の連続再生はchunk schedulingを追加する別段階と明記する。
この上限は描画・編集・保存に適用しない。短いサンプルのために先読みストリーム/専用音声エンジンを新設しない。

- workerにはSendableなplanとPCM値だけを渡す。AVAudioEngine/PlayerNode/AVAudioPCMBufferの所有・操作はplatform adapterの同じactor/queue内に閉じる。main actorで全sampleを計算しない。
- 準備状態を`stopped / preparing / playing / paused / failed`で明示。準備cancelを可能にし、長い生成ループでもcancelを確認する。確保/engine失敗は黙ってreturnせずエラーを返す。
- 一周分を先にscheduleする。ループは`AVAudioPlayerNode`の`.loops`を使う。範囲途中から開始する場合は「残部」→「全範囲loop」を再生前に順番にscheduleし、残部だけが反復しないようにする。
- 実時間の唯一の時計はplayer sample time。一時停止はnodeのpauseを使う。表示更新タイマーは時計を読むだけで、ループや次の小節の発音を起動しない。
- 途中開始・loopの位置は開始offsetとsample数から計算し、loopの実frame数で剰余を取ってからTempoMapでbeatに戻す。練習テンポ変更/seekは新しいgenerationで再scheduleする。
- 一回再生の終了は`.dataPlayedBack`で検知。`.dataConsumed`を曲末とみなさない。callbackはactorへ戻しgenerationを確認、stop/文書切替で無効化する。loop途中の残部完了では停止しない。
- rendererとtransport状態遷移は実機音声と切り離してテスト可能にする。Apple API契約は[AVAudioPlayerNode](https://developer.apple.com/documentation/avfaudio/avaudioplayernode)と使用SDKのheaderで確認済み。

## 5. 鍵盤・楽譜・発音表示

### 鍵盤付きピアノロール

各表示窓/段の左端に縦鍵盤を固定。半音ごとの行とノートの高さを一致させる。
白鍵/黒鍵、C4等の音名、再生中の鍵を表示。音域は曲単位で揃え、ページを送るたびに上下しない。
広い音域は縦スクロール。鍵を押すと短いガイド音で試聴し、離す/キャンセル/画面を閉じると止める。
試聴用nodeをtransportから分け、再生位置や文書に影響させない。VoiceOver/キーボード操作でも音名を識別できること。
ここでいうMIDIキーボードは画面内の鍵盤。外部USB/Bluetooth MIDI入力は将来のCoreMIDI工程。

### 楽譜

「一覧」と「楽譜」は別概念。詳細でも楽譜を選べ、一覧でもピアノロールを使える。
最初の楽譜表示は**単旋律・ト音記号・調号なし（臨時記号で表現）**。音名の表示補助も残す。
五線上の正しい音高、加線、全/2分/4分/8分/16分音符と休符、1付点、符幹・旗、小節線・拍子、タイを実装する。
連桁は初期必須にしない。単に五線上へ丸を並べて「楽譜対応」としない。
小節/拍をまたぐ長い音は表示上の音価へ分解してタイ、空白時間は表示用休符にする。元eventを変更しない。
pitch spellingが有効なら尊重し、なければ既存`Note.name`と同じ決定的な異名同音表を使う。
spellingは音名+臨時記号+octave（例C#4/Eb4）の解釈とMIDI pitch一致を検証。不明形式は診断を出して既定表へ。
臨時記号は同一小節・同一octaveの状態を管理し、必要なナチュラルを省略しない。小節境界でリセット。
五線・歌詞とも第2節の共通x座標を使用。これは拍に比例する練習用表示で、出版用の譜刻ではない。
連符/16分より細かい位置/複数声部・重複音符等、初期範囲外の小節は理由付きピアノロールへ退避する。
音の欠落や近い音価への丸めで五線に押し込まない。対応範囲外でも曲の再生/保存は利用できる。

### カタカナ読み

原因は2点。`TwinkleSample`はIPA/readingを設定しておらず、`SingingView`はreadingを描画していない。
読みの保存フィールドと`WordInspector`は存在する。保存済み値の消失と判断して移行処理を書かない。
きらきら星の英語音節に教材用のIPA/カタカナ近似を入れ、`source.kind = sample`とする。意味の日本語訳とは分離。
一般的な米語を基準とし、diamondを歌の2音節に合わせたサンプル上の扱いも記録する。
両歌唱表示に音節・読みの行を用意。初期は読みON、IPAは切替可能。ReadingのIPA/読み編集は維持する。
未入力は「読み未設定」と分かるようにし、選択から既存Inspectorで入力できる。読みは原音の近似という説明を保つ。
新規サンプルに反映し、既存の保存文書/利用者の手修正は自動上書きしない。
Git外の例示packageは別名で新規生成し、旧ファイルを保持する。一般歌詞の自動発音生成は今回追加しない。

## 7. 受入確認

| 確認対象 | 必須の観測結果 |
|---|---|
| きらきら星 | 12小節/48四分音符拍/42音、96 BPMで30秒（1,323,000 frames、丸め誤差は1 frame以内）。2小節境界で停止・重複・余計な間がない |
| 詳細と一覧 | 詳細は1–2→3–4…→11–12小節へ追従。一覧は4小節×3段が標準幅で読める。切替で位置・音・practiceRangeが変わらない |
| 範囲1回/loop | 3–4小節なら8拍=5秒で1回終了、loopは同じ範囲を反復。途中から再開しても次周は全範囲。末尾の長音を欠かさない |
| UIと音 | 音符/語の選択でseekしない。目盛りseekは音と画面が一致。手動スクロールは音を止めない。pause/stop/曲末の状態が表どおり |
| 時間の難例 | 途中tempo変更と逆変換、弱起、3/4→6/8、不完全小節、休符、またぐ長音、共有event ID、範囲clip、同pitch反復とtieをfixturesで確認 |
| 鍵盤/五線 | C4の行と音、C4–A4の五線上の位置、休符/音価/加線/臨時記号取消/タイが正しい。未対応小節を隠さず退避表示 |
| 発音/保存 | 全42音節にサンプル読み。両画面で表示切替・読み編集・Undo・保存/再読込。手修正、安定ID、未知package添付を保持 |
| 非同期・上限 | prepare中のstop/連続seek/文書置換で古い結果が鳴らない。engine失敗でplayingにならない。5分超を確保前に拒否し編集は可能 |

境界ロジックは表の期待値を直接検証するfixtureテストにし、実装を写しただけのテストを増やさない。
例: beat 0で120 BPM、beat 4で60 BPMならbeat 8は6秒、3秒はbeat 5。練習倍率0.5なら各秒数は2倍。
例: 弱起[0,1)、通常小節[1,5)では1:4の幅。イベント[4,6)は両表示窓に現れても発音は1回。
`native/scripts/swift-tool.sh test`と`native/scripts/build-app.sh`は順番に実行。AGENTS.mdの既存Python2系統も実行。
新ビルドを旧インスタンスと区別して、実画面で日本語・読み・一覧・詳細・鍵盤・楽譜・連続再生・保存を確認。
旧Tkの日本語入力/プレビュー/Word出力の回帰確認もAGENTS.mdに従う。実聴/実画面の未確認は成功に含めない。
通常音声デバイスで連続性を聴けない場合は、PCMの非無音・境界・長さの検証と実聴未確認を分けて報告する。
