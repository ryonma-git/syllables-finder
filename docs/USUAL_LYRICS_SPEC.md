# いつもの歌唱教材仕様

仕様版: 1 / 更新日: 2026-11-19

「いつもの仕様」「いつもの形」「いつもの形式」「いつもの歌唱教材」は、この文書の現在のmain版を指します。Ishibashiのプロジェクトに対応するCodex記録から、2026-11-17〜18の修正指示まで確認して共通仕様にしました。今回のユーザーの明示指示がある場合は、それを優先します。

## 依頼の意味

> 『曲名』を、以下の歌詞から「いつもの仕様」で生成してください。

この依頼で、提供された歌詞をCodexが解釈・検証し、Singing Workspaceで開く曲ファイル、印刷用PDF、編集用Wordを作ります。歌詞だけの新規生成・追加、音源・楽譜・音符・歌詞と音符の対応の作成は、この依頼には含めません。

## 原文と紙面

- 提供された歌詞、順序、繰り返し、括弧内の歌詞を保持します。原文入力をGit外に保存し、明らかな貼り付け崩れや誤字を直す場合も原本を残し、修正を別途記録します。
- 各フレーズに、色なし・音節区切りなしの通し原文を載せます。その下に、アプリ通常の母音核の色分けを使った本文・音節、カタカナ、IPA、文脈に合う単語訳、行ごとの日本語訳を載せます。
- 文の意味欄は日本語訳だけにします。子どもが歌いながら読む紙面に、説明注釈、発音上の判断の長文、別行の連続IPAを追加しません。必要な連音は対応する発音・読みの欄へ反映します。
- 見出し、表示順、デザイン、色はアプリの設定と出力でそろえます。今回の指定がなければ既存の設定を確認して使い、設定がない場合は下表のアプリ標準を使います。過去の特定曲への色指定を全曲の共通指定にはしません。

| 項目 | アプリ標準（仕様版1の確認時点） |
|---|---|
| 注釈の表示順 | 本文・音節 → カタカナ → IPA → 単語訳 → 翻訳 |
| 出力デザイン | 標準 (`standard`) |
| 見出し・番号 / 母音核 | ともに浅葱色 `#0A9CA6` |
| 英語の読み | 単語読み (`word`) |

通し原文は、この注釈の表示順とは別に各フレーズへ併記します。アプリの表示順・印刷設定はMacごとの設定なので、`.songproj` だけを渡して一致すると決めつけません。作成時に採用した表示順・デザイン・色・読みモードをGit外の検証記録に残します。

## 発音と読み

Codexが語の意味・品詞・行の文脈を判断し、音節、IPA、カタカナ、訳の対応を確認します。辞書・アプリ・モデルの出力は候補として扱い、未確認の自動出力をそのまま完成品としません。カタカナは発音の補助であり、英語原文やIPAを読む学習を妨げる過度な表記にしません。

### 英語

- 初期表示と通常のPDF・Wordは「単語読み」にします。単語ごとの読みやすいカタカナとIPAを基本に、文脈に適した弱形を使います。単語読みでは、語境界をまたぐ変化を強くカタカナ化しすぎません。
- 「つながり読み」も同じ曲ファイルで選択できるよう、必要な箇所の別の読み・IPAを用意します。単語読みを上書きせず、既存の読み切替機能を使います。変化のない箇所は共通の読みを使い、切替のためだけに差を作りません。
- つながり読みも単語・音節の発音欄に表示します。紙面に連続IPAの段落や説明を加えません。つながり読みのPDF・Wordを求められた場合は、選択した読みで別名出力します。
- 米国式・英国式は曲や依頼に合わせて一貫させ、採用した基準を検証記録へ残します。指定のない米国のポピュラー曲は米国英語を基本にします。

### フランス語など

- フランス語は、文脈に沿ったリエゾンとアンシェヌマンをIPAとカタカナに残します。エリジオン、鼻母音、語末の黙字、発音する／省略するeも確認します。英語の単語読みの方針をフランス語に流用しません。
- その他の言語も、その言語の発音に基づいて音節・IPA・補助読みを整えます。歌唱版によって変わる箇所や採用上の留保は、児童用紙面ではなく検証記録または納品時の説明に残します。
- 音源を確認していなければ、特定歌手の実演と一致すると断定しません。

## 作成と出力

1. [AGENTS.md](../AGENTS.md) と [SSOT運用](SSOT.md) に従い、両Mac、canonical、GitHub、各作業branchと未commit変更を確認します。共有済みmainと未採用作業を区別し、確認したcheckoutからアプリを再ビルドします。
2. [既存の生成経路](SONG_GENERATION_API.md) で原文・節・語の構造を作り、Codexの解析を曲データへ反映します。自動生成の終了コード0を、発音や訳の完成の証明にしません。既存ファイルや手修正は保全します。
3. 再ビルドしたアプリを絶対パスで選んで曲を開き、原文・読み・IPA・意味を確認します。英語の別読みを用意した場合は、両方の表示と切替を確認します。
4. 同じcheckoutの `SongPrintTool` またはアプリの共有メニューでPDF・Wordを出力します。独自の別レイアウトへ作り直しません。ツールはアプリの設定を自動取得しないため、表示順・デザイン・色・読みモードを明示して一致させます。
5. `.songproj`、PDF、Word、原文入力、検証記録は `~/Documents/SingingWorkspaceExamples` 以下などのGit外へ保存します。両Mac間で生成物が自動同期されるとは扱いません。納品時にファイルへのリンクと、検証・未確認の範囲を示します。

アプリ標準で単語読みを書き出す例（事前にアプリの設定を確認）:

```sh
binary_dir="$(native/scripts/swift-tool.sh build --show-bin-path)"
"$binary_dir/SongPrintTool" /absolute/input.songproj /absolute/output.pdf \
  --order=original,reading,ipa,meaning,translation --design=standard \
  --accent=0A9CA6 --vowel=0A9CA6 --english-reading=word
"$binary_dir/SongPrintTool" /absolute/input.songproj /absolute/output.docx \
  --order=original,reading,ipa,meaning,translation --design=standard \
  --accent=0A9CA6 --vowel=0A9CA6 --english-reading=word
```

`--english-reading` は英語の歌詞がある曲で使います。つながり読みの出力には `connected` を指定します。既存の同名PDF・Wordを置き換える場合は、先に必要な原本を保全します。

## 完成前の確認

- 提供された全行、語順、繰り返し、括弧内の歌詞が保持されている。
- 通し原文、単語、音節の綴りが対応し、IPAとカタカナ、単語訳と行の日本語訳が文脈に合っている。
- 空欄・発音保留・警告を確認し、未解決の項目があれば完成と混同せず報告する。
- アプリで曲を開け、保存した読みを再表示できる。英語の読み切替で原文・音節・単語読みが失われない。
- PDFとWordの全ページを実際に描画して確認し、文字化け、IPAの欠落、はみ出し、読みにくい改ページがない。
- 説明注釈や別行の連続IPAが混入しておらず、訳欄は日本語訳だけになっている。

構造検査、アプリ実画面、PDF/Wordの全ページ、録音照合は別の検証です。未実施・skipを成功として報告しません。

## この仕様を最新版に保つ

この文書を両Mac共通の仕様の正本とし、Codexの過去の会話だけを再現条件にしません。関連する発音・音節・読み切替・保存・表示・PDF/Word出力の実装を変更した作業では、同じ作業内で本書との整合を点検します。継続的なユーザー希望や再現手順が変わったら、仕様版・更新日・変更履歴を更新し、関連実装とともに通常のSSOT手順でcommit・共有します。一曲だけの指定は、その曲の検証記録へ残します。

実装だけの修正で教材の約束や手順が変わらない場合は、仕様版を機械的に上げません。関連変更のレビューで本書を確認したことを記録します。将来の更新は各作業時に行うもので、常駐処理や自動監視が設定されたという意味ではありません。
