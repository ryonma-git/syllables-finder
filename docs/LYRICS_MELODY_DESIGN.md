基点 `1a0af6b`（`codex/native-singing-foundation`）。作業branch `claude/lyrics-melody-alignment`。`main`へはmergeしない。
実装状況は本書末尾の「実装段階」と [WORK_LOG.md](WORK_LOG.md)。判断の要約は [DECISIONS.md](DECISIONS.md) ADR011〜016。

## 1. 目的の再定義

このアプリの本来の目的は、**利用者が実際に歌う曲**（伝承曲に限らない）について、歌詞の意味・発音と「どの音で何を歌うか」を練習できる教材を作ること。

- 歌詞・MIDI・音源は**利用者が自分で用意し、権利処理済みである前提**で扱う。アプリは取得・配布をしない。
- 利用者が入れた歌詞・音源は、その Mac の `.songproj` の中だけに保存する。Git・内蔵サンプル・テストには入れない。
- 内蔵サンプルは従来どおり伝承曲・自作のみ（ADR009）。旧READMEの「既存楽曲の歌詞本文は扱わない」は「アプリが既存楽曲を同梱しない」の意味に改める。
- 音程採点・歌声合成は引き続き対象外。参考音源の**解析**（割付の手がかり）は後続段階で対象に入れる。

## 2. 全体の流れ

どの入口から入っても、最後は同じ「音符と音節の対応を直す画面」に到達する。

```text
歌詞を入力（言語を選ぶ）
  └─ 言語別の音節分割 → 音節候補（すぐに表示・手修正可）
旋律を用意（いずれか・組合せ可）
  ├─ A. MIDI鍵盤／画面鍵盤でステップ入力        ← 今回実装
  ├─ B. MIDI鍵盤でリアルタイム録音＋クオンタイズ ← 設計のみ
  ├─ C. MIDIファイル（SMF）を読み込む            ← 今回実装
  ├─ D. MusicXML を読み込む                      ← 後続（MUSIC_IO）
  └─ E. 歌声／原曲音源 → 旋律推定                ← 後続
割付（一音符一音節を基本仮説）→ 候補と要確認箇所を表示
  └─ 人が直す → 直した所は固定 → 前後だけ再計算
参考音源（原曲・自分の歌唱・部分の歌い直し）で割付を補助 ← 後続
確定データから 歌唱画面／楽譜／Word・PDF を生成
```

## 3. 言語層：音節分割

### 3.1 二段階の区別

「言葉としての音節」と「その曲での歌い方」を別に保存する。

| 層 | 保存先 | 変わる契機 |
|---|---|---|
| 言語的な音節（綴りの区切り、読み、強勢） | `Syllable`（`Word`の子） | 歌詞入力時の自動分割、人の分割修正 |
| 歌唱上の割付（どの音節をどの音符で歌うか、メリスマ、エリジオン） | `Alignment` | 割付計算、人の割付修正、参考音源 |

割付の都合（例：2音節の語を1音に詰める）で `Syllable` を書き換えない。エリジオンは「2音節を1音符へ」の `Alignment` で表す。

### 3.2 分割エンジン

`SongCore/Syllabification` に、Foundation だけで動く規則ベースの分割器を置く（外部辞書・ネットワークなし）。

- 入力：単語の表層（句読点付き）と言語コード。出力：音節テキスト列（句読点を除き、連結すると語の文字に戻る）、強勢の推定（分かる言語のみ）、別案（ある場合）、注記。
- 生成した値は `FieldSource.rule`（規則による候補）。手修正は従来どおり `manual` で保護。
- 利用者は結合アクセント（U+0301、例 `мо́ре`）で強勢を明示でき、分割器はそれを優先する。
- 未対応言語は「音節未分割」の単語として残し、手動で区切れる（入口を塞がない）。

### 3.3 言語ごとの規則（優先順：独・西・仏 → 伊・羅・露 → 英・日・韓 → 中）

| 言語 | 母音核のまとまり | 子音の分け方 | 強勢 | 注意（別案・後続） |
|---|---|---|---|---|
| de | ei ai au eu äu ie ey ay・長母音 aa ee oo | 母音間の子音は最後の1単位を次へ。sch ch ck ph th qu は1単位 | 語頭音節。be/ge/er/ver/zer/ent/emp 接頭辞は次 | 複合語境界は推定しない |
| es | 強母音 a e o 同士は分立、弱母音 i u と強母音は二重母音。í ú は分立 | 1子音は次へ。子音+l/r（bl br cl cr dr fl fr gl gr pl pr tr）と ch ll rr は分けない | アクセント記号 → 母音/n/sで終われば後ろから2番目、他は最終 | qu/gu+e/i の u は黙字 |
| fr | ai ei au eau ou eu œu oi ui ie（1核） | 子音+l/r は分けない。ch ph th gn qu gu は1単位 | 最終（無音eを除く） | **歌唱の規則で語末 e/es/ent を1音節に数える**。話し言葉の数は別案。語間の省略は割付で扱う |
| it | 弱母音 i u と他の母音は二重母音 | es と同様。gl gn sc ch gh は1単位 | 語末のアクセント記号、なければ後ろから2番目 | 歌唱で分けて歌う i-o 等は割付/手修正 |
| la | ae oe au（教会式） | 子音+l/r は分けない。x は前、ch ph th qu gu（+母音）は1単位。gn は次へ（A-gnus） | 2音節語は語頭 | 母音間の i は子音 j。発音方式（教会式／ドイツ式等）を文書に保存 |
| ru | 母音字ごとに1核 | 1子音は次へ。й は前、л м н р の後で分ける、重子音は分ける。ь ъ は直前の子音に付く | ё と明示アクセント | 綴りから強勢は決められない。明示を推奨 |
| en | ai ay ea ee ei ey ie oa oe oi oo ou ow oy ue ui au aw ew・語末の黙字 e | V-CV を基本、VC-CV、子音+le は1音節 | 推定しない | 規則の例外が多い。候補として扱い手修正前提 |
| ja | かな1モーラ＝歌唱単位。小書き文字は前に付く。ん・っ・ー は独立モーラ | — | — | 漢字は macOS の読み推定（CFStringTokenizer）で読みを付け、推定と明示。`漢字（かんじ）` で読み指定可 |
| ko | ハングル1字＝1音節 | — | — | 連音化など発音は後続 |
| zh | 漢字1字＝1音節（試験的） | — | — | 普通話のピンインと声調を読み欄へ（多音字は要確認）。広東語は別言語 |

日本語はモーラを歌唱単位とするため、日本語の `Syllable` は1モーラを表す（読み欄にカタカナ）。モーラ/音節の二層が必要になったら `Mora` を使う。
ポルトガル語・チェコ語・ハンガリー語は、扱いたい曲が出た時点で追加候補にする。

## 4. 音楽層：声部（パート）

### 4.1 方針

保存形式は**最初から複数声部を持てる統合形式**。単声曲は「声部が1つの曲」。声部数は `parts` の数から分かり、別管理しない。SATB固定にしない。

```text
SongDocument
  music.measures / tempos / meters   ← 全声部で共通の小節・拍（同期の基準）
  music.parts[]                      ← 声部：名前・略称・音部記号・歌う歌詞の順序
  music.events[].partID              ← 各音符・休符はどれか1つの声部に属する
  alignments                         ← 声部の音符と音節を結ぶ（声部ごとに別の割付）
  phrases/words/syllables            ← 歌詞と意味・発音は全声部で共有
```

- `Part.phraseIDs`：その声部が歌う歌詞の Phrase 順（繰返し可）。`nil` は文書の全 Phrase を順に歌う。ソプラノとアルトで入り方・繰返しが違う場合に使う。
- 声部間は「録音開始から何秒」ではなく**小節・拍（Beat）で揃える**。別々に入力した声部も同じ時間軸に載る。
- 声部の書き出し＝その声部だけを含む同形式の文書。取り込み＝既存文書へ声部を追加（小節・拍子が矛盾したら拒否して理由を表示）。
- 音部記号は `treble`／`treble8vb`（テノール）／`bass`。

### 4.2 保存形式 schemaVersion 2

| 追加・変更 | 内容 |
|---|---|
| `Music.parts: [Part]` | `Part(id, name, abbreviation, clef, phraseIDs?)`。音符があれば1つ以上必須 |
| `MusicalEvent.partID: UUID?` | v2 では音符・休符すべてに必須、存在する声部を参照 |
| `Phrase.language: String?` | その行の言語（`nil`は文書の言語）。多言語の曲用 |
| `FieldSource.Kind.rule` | 規則による候補 |

移行：version 1 を開くと純粋関数で v2 へ変換（声部「旋律」を1つ作り、全 event をそこへ入れる。旧 `Notation.part` に複数の値があれば値ごとに声部を作る）。
移行した文書を保存すると、元の `document.json` を package 内の `preserved/document-v1.json` に残す（既にあれば上書きしない）。
v2 を旧版アプリで開くと「対応しない形式」で開かない（旧版の既存動作。黙って壊さない）。

## 5. 旋律の入力

### 5.1 A. ステップ入力（今回実装）

楽譜ソフトの標準的な方式。演奏技術が要らず、ゆっくり正確に入れられる。

- 歌う画面の「旋律を入力」で入力パネルを開く。対象の声部、音価（全〜16分・付点）、入力位置（カーソル）を表示。
- **MIDI鍵盤**（CoreMIDI、全入力ポート）または**画面上の鍵盤**を押すと、カーソル位置に音符を置き、カーソルを音価分進める。休符ボタン、1つ戻す。
- 入力は**上書き**：同じ声部でその時間に始まる音は置き換え、手前から食い込む音は短くする（楽譜ソフトのステップ入力と同じ）。画面に「同じ声部の既存の音は上書き」と明示。1操作＝1 Undo。
- 小節をまたぐ長さは記譜でタイに分けて表示する（データは1音のまま）。タイで別の音価を足す操作は後続。
- 小節は拍子から自動生成して保存する（入力で曲が伸びたら小節も伸ばす）。

### 5.2 B. リアルタイム録音（設計のみ）

カウントイン後にクリックを聴きながら弾く。生の演奏（秒と velocity）を別に保持し、グリッド（例：16分・3連）へのクオンタイズは何度でもやり直せる。
ゆっくり弾いた演奏を指定テンポへ伸縮できる。録音遅延は設定で補正する。フレーズ単位で録音し、既存の小節へ上書きする範囲を明示する。

### 5.3 C. MIDIファイルの読み込み（今回実装）

[MUSIC_IO.md](MUSIC_IO.md) の MIDI 節に従う。SMF format 0/1・PPQ。format 2・SMPTE は理由付きで拒否。

- トラック（format 0 はチャンネル）ごとに声部候補を作り、利用者が読み込む声部を選ぶ。トラック名を声部名の初期値に。
- tick/PPQ → Beat を有理数で正確に変換。テンポ・拍子メタを全声部共通の地図へ。
- 同音の重なりは FIFO で対応付け、velocity 0 は note-off。未対応の note-off・壊れたファイルは診断して拒否/警告。
- 読み込んだ原ファイルは package の `source/` に保持。歌詞メタ（lyric）は今回は取り込まない（割付で歌詞を載せる）。
- 既に音符がある文書へは「声部として追加」または「置き換え」を選ぶ。置き換えで消える音符への割付も同時に削除（参照整合性を保つ）。

### 5.4 D・E（後続）

MusicXML は MUSIC_IO のゲートに従う。音声からの旋律推定は、一人の歌声／鼻歌を対象に、外部モデルを同梱せず、利用者が選ぶローカル処理として追加する。歌詞付きの歌声は、MIDI化で歌詞の発音情報を捨てないよう、音高列と発音タイミングを別々に保持する。

## 6. 割付：一音符一音節を軸に

### 6.1 単位

- **歌われる音**＝休符でない音符。同じ声部で `tieGroupID` が同じ連続音符は1つの歌われる音（タイ）として数える。
- **歌う単位**＝声部の歌詞順（`Part.phraseIDs`）に並べた音節（日本語はモーラ）。
- **アンカー**＝人が確定した割付（`Alignment.userEdited == true`）。再計算で動かさない。

### 6.2 計算

アンカーで区切られた区間ごとに、音節列 S と歌われる音列 N を単調に対応させる動的計画法。

1. 基本は **1音節＝1音**（コスト0）。
2. 音が余る（N > S）：ある音節を複数の音に伸ばす（メリスマ）。追加の音1つにコスト。短い音価・順次進行（2半音以内）・同じ語の母音の上なら安い。
3. 音節が余る（S > N）：隣り合う2音節を1音に載せる（エリジオン）。語境界で「母音で終わる語＋母音で始まる語」、または語内の母音連続（例 dia-mond）なら安い。それ以外は高い。
4. 歌詞の句読点・行末は休符や長い音の前に来ると安い（句の切れ目を合わせる）。強勢が分かる音節は強拍に来ると安い。
5. 最小コストの割付を採用。関係は `oneToOne`（1対1）、`tie`（タイで結ばれた1音）、`melisma`、`elision`。

計算結果は「提案」として表示し、次を要確認箇所として示す：メリスマ・エリジオンの位置、区間の音節数と音数の差、音が足りず載らなかった音節、歌詞のない音。
適用は1回の Undo。再計算は `userEdited == false` の割付だけを置き換える。人が音節を別の音へ動かすとアンカーになり、その前後だけ再計算できる。

### 6.3 AI の位置付け

まず決定的な規則で割付を作る。曖昧な箇所の候補選びに AI（[AI_PROVIDERS.md](AI_PROVIDERS.md)）を使う場合も、同じ候補形式を返させ、アンカーと検証を通してから適用する。AI は正解の復元ではなく候補の提示。

## 7. 参考音源（後続）

| 参考音源 | 役割 | 保存 |
|---|---|---|
| 原曲の録音 | 原曲の歌い方・入りの確認 | package `media/`（利用者のMacのみ） |
| 自分で歌った録音 | 教材で採用したい割付を示す | 同上 |
| 一部分の歌い直し | 指定範囲の修正を示す | 同上、範囲（Beat）付き |

原曲と歌い直しが食い違う場合、区間ごとに「歌い直しを採用」を選べる。MIDIが基準、歌声は割付の判断材料。解析は歌い終わってから行う（リアルタイム追従はしない）。

## 8. 楽譜（五線譜）の表示

### 8.1 問題（2026-09-28 に再現）

旧表示は符頭が譜線間隔の約半分の大きさで線・間に接しない、ト音記号・拍子記号が五線の範囲に収まらない、五線上に小節線がない、8分・16分の旗が「♪」文字の貼り付けで符幹から離れる、連桁がない。このため音符が五線から浮いて見えた。

### 8.2 記譜の基準

すべての寸法を**譜線間隔（staff space, sp）**を単位に `SongCore/StaffEngraving` で計算し、描画は座標を塗るだけにする（フォントの字形位置の推測をしない）。

| 要素 | 規則 |
|---|---|
| 符頭 | 高さ 1sp、幅 約1.3sp、やや傾けた楕円。線上の音は線が中心を通り、間の音は上下の線に接する |
| 符幹 | 長さ 3.5sp。第3線（中央線）以上は下向き（左側）、未満は上向き（右側）。加線上の音は中央線まで延ばす |
| 旗・連桁 | 8分・16分は拍（6/8等は付点4分）ごとに連桁。単独なら旗を符幹の先に描く |
| 加線 | 五線外の線位置ごとに符頭より少し長い線 |
| 臨時記号 | ♯♮♭を図形で描き、符頭の左に置く。小節内の状態で取消を判断（既存の規則） |
| 付点 | 符頭の右。線上の音は上の間へ |
| タイ | 符頭の符幹と反対側に弧 |
| 休符 | 全休符は第4線から下げ、2分休符は第3線に乗せる。4分・8分・16分休符は図形 |
| 小節線 | 五線の高さだけ。曲末は終止線 |
| 音部・拍子 | 音部記号は字形の外接矩形を五線基準の枠へ合わせる。拍子の数字は各2spの高さで上下2段 |
| 歌詞 | 五線の下。音節は符頭の位置から、同じ語の音節間にハイフン、メリスマは延長線 |
| 複数声部 | 声部ごとに1段、左端を括弧でまとめる（システム） |

横位置は拍に比例する（歌詞・再生位置・ピアノロールと同じ時間軸を共有するため。ADR010）。出版譜の非線形間隔は将来の別投影。短い音が詰まる場合は表示倍率で広げる。

## 9. 画面への追加（歌う画面）

- ツールバー／メニュー：「歌詞を追加…」に言語選択と「音節に分ける」（既定ON）、「旋律を入力…」、「MIDIファイルを読み込む…」、「歌詞を音符に割り当てる…」。
- 声部選択：表示・入力・割付の対象声部。楽譜では全声部を段で表示し、ピアノロールは選択声部を濃く表示。
- 割付の確認シート：提案の要約（1対1／メリスマ／エリジオンの数、差のある区間）、要確認箇所の一覧、適用/取消。

## 12. 利用者に確認したい未決事項

1. ラテン語の既定発音：教会式（イタリア式）でよいか。ドイツ式等は曲ごとの選択にする案。
